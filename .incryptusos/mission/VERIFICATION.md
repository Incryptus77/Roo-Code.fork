# Roo-Code.fork — Hostile Test and Owner Acceptance

## First real end-to-end scenario
A source-pinned feature/license comparison identifies reusable components and demonstrates a behavior-preserving differential test in the intended adopter.

## Domain failure matrix
- Fork exists not equal current usable extension
- Licenses unchanged by port
- Untrusted tool permissions not inherited

## Universal negative and recovery tests
- Wrong user, tenant, revoked token or device is rejected by the owning domain.
- Provider timeout/retry does not duplicate durable payment, order, saved record or notification.
- Nested compiler/test child exit and first failure are retained; an outer green wrapper cannot hide a red child.
- Offline/stale/unknown data is not reported as live or final.
- Invalid source file/prompt/web result cannot grant new tools/permissions.
- Original accepted client data and workflow survive upgrade and rollback.
- Deployed desktop/mobile/backend and real domain readback distinguished from fixture success.

## Evidence states
DESIGNED, SOURCE_PRESENT, TESTED_FIXTURE, INTEGRATED_TESTED, HOST_VERIFIED, DOMAIN_EFFECT_VERIFIED, OWNER_ACCEPTED, FAILED, BLOCKED and NOT_OBSERVED. Source publication cannot upgrade an absent Windows host to HOST_VERIFIED.

## Exit criteria
Evidence of actual first proof, actual negative tests, crash/restart, original consumer compatibility and a functioning rollback. Continue next useful product slice. Store host receipts and move evidence under `.incryptusos/audits/` and active handoff under `.incryptusos/agent_comms/`.
